Use callouts to break out short asides — context, caveats, or pointers — that you don't want buried in a paragraph. Prefer callouts to bold-italic emphasis for anything more than a few words. rd-cols collapses to a single column under ~720px. Lazy alternative content. First tab is active by default; arrow keys navigate.

Tabs are good for the same content rendered three ways: language variants, before/after, examples by stack.

They are not for hiding important decisions — humans scanning the doc will miss whatever isn't on the active tab.
  • Same example in multiple languages.
  • Before / after code comparisons.
  • Optional deep dives that interrupt the main flow.
  • Hiding important steps. Use sections instead.
  • Long content. Tabs cap at a screenful of comfortable reading.
  • Search-critical content (only the active tab is visible to Ctrl+F on first load).

Use rd-detail for content that's relevant but not on the main path — appendices, full error logs, derivations. Native <details> under the hood, so it works without JS and remains keyboard-accessible.

Free-form HTML lets agents drift. One doc invents <callout>, the next uses <note>, the third leaves it as bold-italic prose. The reader experience fragments and the agent has no way to verify their output.

A closed vocabulary plus a validator makes both ends of the loop reliable: the agent always knows what's allowed, and the reader always sees the same components.
