# richdoc — diagram language guide

Every `<rd-diagram lang="…">` value is a Kroki-supported diagram type. This page is editorial guidance — for the authoritative list of supported types and formats, run:

```bash
./diagram-cli/diagram types
```

(from `agent-skills/diagram/`, or any other Kroki-compatible tool).

## Pick by intent

| If you want to draw … | Use `lang="…"` | Notes |
| --- | --- | --- |
| Flowchart, sequence, state, gantt, ER (simple), pie | `mermaid` | The default; widest familiarity. |
| UML sequence, class, activity, deployment, use case, component | `plantuml` | Fuller UML; supports `!theme`. Dark-mode docs auto-inject `cyborg-outline`. |
| C4 model (Context / Container / Component / Code) | `c4plantuml` | C4 macros over PlantUML; same `theme` rules. |
| Service / architecture / infra topology | `d2` | Modern syntax, minimal ceremony, strong defaults. |
| Directed graph with explicit styling | `graphviz` | DOT language. Best when you want node/edge attributes per element. |
| Database schema (ERD) | `dbml` | Tables + refs in compact syntax. Renders an ERD. |
| BPMN business process | `bpmn` | XML; usually generated by a tool. |
| ER diagram, alternative syntax | `erd` | Chen-style ER syntax. |
| ASCII-art-as-code box-and-arrow | `svgbob` | Renders ASCII line drawings as crisp SVG. |
| Tiny UML diagrams (one-liners) | `nomnoml` | Compact class/sequence/use-case. |
| Hand-drawn-looking sketches | `excalidraw` | JSON from Excalidraw exports. |
| Architecture / deployment in pure code | `structurizr` | C4 model DSL. |
| Math typesetting with diagrams | `tikz` | LaTeX TikZ. Heavy renderer; expect longer round-trips. |
| Block, sequence, activity, network, packet, or rack diagram | `blockdiag` / `seqdiag` / `actdiag` / `nwdiag` / `packetdiag` / `rackdiag` | The blockdiag family. |
| Wave/timing diagrams | `wavedrom` | Digital signal timing. |
| Cable / wiring diagrams | `wireviz` | Cables and connectors. |
| Pseudo-CAD box-and-line | `pikchr` | SQLite-flavoured PIC dialect. |
| Bit-field / byte-layout illustration | `bytefield` | Protocol packet layouts. |
| Statistical / data viz from a spec | `vega` / `vegalite` | Use `rd-chart` for the common dashboard cases; `rd-diagram lang="vegalite"` for full Vega-Lite spec authoring. |
| Plain SVG ASCII art | `ditaa` | DIAgrams Through Ascii Art. |

## Default = mermaid

If you're unsure and the diagram is a flow, sequence, or state machine, use `mermaid`. It's the most documented, has the best error messages, and the syntax is easy for an agent to generate.

## Themes

`theme="<name>"` is only meaningful for `lang="plantuml"` and `lang="c4plantuml"`. Author-written `!theme` directives in the source are always respected. Dark-mode docs auto-inject `cyborg-outline` unless overridden.

## Endpoints

The default endpoint is `https://kroki.io` (Kroki's free public service). Override per-element with `endpoint="…"` or doc-wide with `<rd-page diagram-endpoint="…">`. For sensitive content, point at a self-hosted Kroki (Docker image: `yuzutech/kroki`) or for PlantUML-only an upstream `plantuml/plantuml-server`.

## Failure modes

- **CompressionStream missing** (Chrome <90, FF <113, Safari <16.4): source falls back to `<rd-code>` inline.
- **Endpoint unreachable** (network, CORS, 4xx/5xx): source falls back to `<rd-code>` inline.
- **Syntax error in source**: Kroki returns 4xx, source falls back to `<rd-code>` inline. Open the network panel for the error body, or fix locally with `diagram render --input file.<ext> --output /tmp/out.svg`.
